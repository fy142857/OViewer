# 每日自动签到

## 站点机制

EHWiki 将每日奖励称为 **Dawn of a New Day**，每天 UTC 00:00（北京时间 08:00）重置。登录后访问新闻页或画廊详情页触发，普通列表页不能替代这一请求。官方也说明，没有显示事件提示时仍可能已经获得奖励，不能把普通 HTTP 200 当作领取成功。

- [Dawn of a New Day](https://ehwiki.org/wiki/Dawn_of_a_New_Day)
- [Technical Issues / HentaiVerse](https://ehwiki.org/wiki/Technical_Issues#HentaiVerse)

EH、EX 模式均使用官方 Wiki 链接的 `https://e-hentai.org/news.php`，共享当前账号的每日记录。未发现官方对 EX 独立签到奖励的说明，因此不分别请求两个站点，也不访问 HentaiVerse 战斗或随机遭遇链接。

## 用户行为

- 设置“站点”区域提供默认开启的“自动签到”、今日状态以及手动签到/重试。所有应用文案支持中文、英文；奖励正文保留站点返回的原文，不推算数额。
- 首帧后、登录成功、返回前台、开启自动签到时检查；持续前台使用跨 UTC 日期时再次检查。请求等待现有代理准备，且不阻塞首页或阅读。
- 应用关闭或后台停留时不安排新的请求；已经发送的请求可以完成，成功弹窗延后至前台。没有操作系统后台任务。
- 明确 Dawn 事件才显示“签到成功”弹窗并保存“今日已签到”。其他弹窗存在时排队，同账号同 UTC 日期只自动展示一次。退出登录或跨日丢弃过期弹窗。
- 页面正常但没有事件提示时显示“已尝试，未确认领取；可能已在其他设备领取”。登录页、验证页、异常响应和超时均不写入成功状态。
- 自动请求每天最多三次：首次及额外两次重试，失败后等待 5、30 分钟。手动重试的最短间隔为 30 秒，不增加自动请求预算；关闭自动签到仍可手动操作。

## 实现与持久化

`DailyCheckInRepository` 访问固定新闻地址，禁止该请求跟随重定向，整体 20 秒超时包含等待代理；取消令牌终止等待和请求。`DawnParser` 只解析事件区域 `#eventpane` 的明确 Dawn 文案，排除新闻/评论正文和脚本，保留奖励段落。

`DailyCheckInCubit` 负责前台调度、并发合并、日期和账号隔离。开关关闭、退出登录及会话变化会使旧任务失效。持久化写入串行执行，内存记录防止在写入完成前快速切换账号产生重复请求。

`DioClient` 提供可选响应观察回调，并在 GET 请求开始时捕获观察范围和 Cookie 会话版本；观察回调出错不会影响画廊请求。浏览 EH/EX 画廊详情页时收到明确 Dawn 提示也会确认签到，避免新闻请求与画廊请求竞争导致漏记。回调不处理其他站点、不执行返回页面中的脚本。

本地 SharedPreferences 保存 `auto_check_in` 和按会员 ID 隔离的 `daily_check_in_<id>`，包含 UTC 日期、状态、自动尝试次数、上次/下次尝试时间、奖励摘要和是否已提示。签到记录不额外保存 Cookie 或密码。损坏记录重新初始化，应用被中断时遗留的“签到中”恢复为“未确认”。本地保存失败会在设置中提示，不能保证跨重启去重。
