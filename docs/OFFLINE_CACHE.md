# 离线缓存

## 使用

详情页的下载按钮会先显示漫画标题、页数及 EH/EX 来源，确认后进入侧栏“下载”队列。来源取自详情请求，不随后来切换的站点改变。继续下载时需使用原来源站点；无法确定来源的旧任务先选择来源并验证目录。

确认窗口每次默认“全部”，也可选择“自定义范围”，输入 `1-20,35,50-60` 等多段页码。页码从 1 开始，区间包含两端，支持中英文逗号；重复、重叠和相邻区间自动合并。空值、倒序和越界范围不能提交。同一本再次下载时取范围并集，仅补下新增、缺失或损坏的页面；选择全部可补齐整本，不删除已有文件，也不重置阅读进度。下载卡片与 Android 通知按目标页数显示进度，部分完成显示“所选范围已完成”。

部分下载不再等待整书目录。首次先读取目录首页确认总页数及分页大小，再只取所选范围覆盖的目录分页；例如每个目录分页含 20 张图片时，选择 `401-402,810` 只请求第 1、21、41 个目录分页，不顺序读取中间分页。已取得的目录和分页大小持久保存，暂停、重启、同一分页内追加范围可复用；新增范围只补取缺少的分页。阅读范围外页面时复用已知目录，其余按当前可见页与预读窗口按需获取，不会自动扫描整书目录。

设置中的“离线缓存”分组独立显示文件占用，并提供两个设置：同时下载漫画数为 1–3 本，默认 2 本；全局图片并行数为 1–6 张，默认 4 张。图片额度由全部活动漫画共享。调低并发允许在途请求收尾，之后按新上限运行；设置保存失败不改变调度配置。

已有有效缓存时，从详情、历史或下载页进入阅读器会优先使用对应来源的本地书籍。保留原书页码和总页数；新建部分任务首次从最小选中页开始，后续恢复阅读进度，显式跳页优先。有效本地页不发起对应网络请求；缺页及损坏页尝试普通阅读缓存与联网加载，失败显示重试。未缓存邻页沿用设置中的预加载数量与图片链接领先窗口。

联网阅读仅写入普通图片缓存，不改变永久下载范围或完成进度。永久修复仍通过“修复缓存（联网）”执行，范围外页面显示“加入离线下载（联网）”。不同站点或已失效会话禁止网络回退并提示处理，本地文件仍可阅读。后台下载补齐当前已显示的网络图片时保留当前帧，离开该页后优先使用本地文件。

离线图片、目录、封面及阅读进度持久化保存。左右翻页、反向阅读、纵向阅读、动图和保存图片使用现有阅读器。退出登录、切换站点、清理普通图片缓存不删除离线文件；手动删除任务会一并清理文件。删除失败保留记录供重试。

## 后台与恢复

Android 使用单一 FlutterEngine 和 `dataSync` 前台服务，在后台保留同一个调度器、数据库和认证上下文。下载通知显示汇总进度并提供暂停；活动结束后停止服务并释放唤醒锁。通知权限拒绝不弹额外提示、不阻止下载，也不反复请求权限。

iOS 进入后台暂停，回到前台只恢复因后台暂停的任务。Android/iOS 进程结束后都保留有效页面，下次打开不自动联网续传，需要用户点击继续。Android 系统强制停止、系统后台时限或厂商电池策略可能中断服务，不提供强杀或重启后自动下载保证。

## 存储与边界

- 数据库 schema 6 保存目标范围、目录分页大小和已知页码的目录有效状态；尚未请求的分页不填充虚假页面记录。schema 3/4/5 升级保留任务目标、文件和进度，旧的完整目录仍可复用。原书总页数、目标页数和整本完成状态分别计算，部分完成只要求所选页码的目录齐全，不用部分完成冒充整本缓存。
- `(source, gid, token)` 派生独立目录标识。`Documents/offline`（Android 为应用 Flutter 私有目录下 `offline`）不与图片缓存混用，不参与图片缓存配额及云备份。
- 二进制响应写入唯一 `.part`，检查响应长度、格式及可解码性，计算 SHA-256 后原子改名，最后登记页面完成；登记前中断留下的文件在启动恢复时清理。
- 每页最多三次下载尝试，目录并发上限为 1；逐个校验所需目录分页的来源、页码范围、分页大小及条目完整性，仅调度目标范围内图片。分页规则变化时最多重新读取首页并修正一次。暂停、删除和会话变化取消请求，过期任务不能登记页面。只有全部目标页目录已验证且文件有效才完成；目录刷新后范围越界会暂停并提示重新选择全部，不静默裁剪。重新验证目录时保留已有文件，确认页面标识改变后才丢弃对应旧文件。
- 普通离线列表与有效本地页读取不访问画廊网络；缺页阅读可联网并使用普通缓存，永久下载仍由下载任务管理。站点切换与登录变化会暂停原任务，不跨来源发送请求。

## 验证入口

```text
flutter test --no-pub test/offline
flutter test --no-pub
python -m scripts.versioning.analyze
python -m unittest discover -s scripts/tests -v
android/gradlew :app:testDebugUnitTest
```

Windows 本机 Gradle 如遇 `Unable to establish loopback connection`，先检查 Java 调用栈；若是 `UnixDomainSockets.connect` 且临时目录过长，可为本次命令设置 `JAVA_TOOL_OPTIONS=-Djdk.net.unixdomain.tmpdir=<较短的已存在目录>`。也可使用候选 Android 工作流的 `offline_emulator_apk=true` 构建隔离测试包；该包的应用 ID 为 `com.oviewer.oviewer.offline_test`，不覆盖原应用，不能作为正式发布产物。

本机运行 `python -m scripts.offline_fixture_server`，再对测试模拟器执行 `adb -s <模拟器序列号> reverse tcp:8765 tcp:8765`。测试应用通过 `127.0.0.1:8765` 代理及 ADB 转发访问 `10.0.2.2:8765` 样例地址，获取目录和 PNG/JPEG/GIF/WebP，避免依赖宿主机 NAT 回环访问。测试入口 `test_driver/offline_validation.dart` 使用生产 UI、存储、调度和原生服务，仅把 EH/EX 的 HTML/API 请求映射到此服务器。普通发布入口不接受该映射，也不会设置测试代理。

`/control?delay=2` 设置单页响应延迟；`/control?enabled=0` 让后续请求失败；`/control?reset=1` 清除请求统计；`/stats` 返回请求路径与图片请求峰值。验收需要记录后台/锁屏下载、暂停及恢复、退出进程、断网后本地阅读、来源隔离、设置变化和清缓存保留下载等证据。

部分下载的自动真机验收入口为 `test_driver/partial_download_acceptance.dart`。启动同一 fixture 服务并设置 ADB reverse 后，在命令环境设置 `OVIEWER_OFFLINE_TEST=1`，以 Flutter 3.16 执行 `flutter build apk --debug --no-pub --target test_driver/partial_download_acceptance.dart --target-platform android-arm64`，只安装到独立测试包。入口实际操作范围弹窗、下载工作器和阅读器，验证部分下载、模拟断网、联网重试及补齐整本；日志以 `[issue75-acceptance] PASS` 或 `FAIL` 收尾，不访问真实 EH/EX 画廊。

按需目录验收使用同一服务与隔离包，将上述 target 改为 `test_driver/sparse_index_acceptance.dart`。它记录真实 HTML 请求，验证 120 页、20 个目录分页时，首次只请求首页和两个所选分页；同分页追加零请求，跨分页追加一次请求，阅读缺页只读取可见及预读范围所需分页。结果以 `[sparse-index-acceptance] PASS` 和 JSON 请求列表输出。
