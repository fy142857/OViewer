# 启动流程与性能验证

## 阶段及依赖

1. `main` 读取本地偏好并初始化 Cookie，建立依赖；应用保存的 EH／EX 站点，生成设置初始快照。此阶段不探测代理、不等待容量扫描，也不解析标签词库。
2. `runApp` 显示首页骨架、导航及保存的主题、语言和布局，历史记录按既有规则立即预读。
3. 等待首帧完成栅格化后，由 `StartupTasks` 启动独立的网络准备、缓存维护、词库加载任务。某个任务失败不会阻断其他任务。
4. `NetworkPreparation` 统一准备代理。Dio、图片下载、更新检查和内嵌网页准备等待同一就绪状态；已缓存的图片、本地历史和页面交互不依赖网络准备完成。
5. 词库就绪后通知标签和搜索联想局部刷新，不修改输入文字、光标、选区和输入法组合状态。

必要本地初始化失败时显示可重试界面。初始化重试清理未完成的依赖注册，避免重复注册。

## 代理及缓存约束

- 手动代理优先；没有手动代理且启用自动代理时，先检查环境代理，再检测 VPN。
- VPN 接口查询上限 500ms；每个主机的九个端口并行探测，各连接上限 500ms。先检查本机，Android 未命中才检查模拟器地址。同组多个端口可用时保留既有端口优先顺序，成功连接立即关闭。
- 自动探测未命中或异常时保留既有直连回退；手动代理不擅自回退。设置加载复用启动探测；用户修改配置后，旧结果失效，原有等待者跟随最新配置。
- 图片缓存容量从创建管理器时生效，启动扫描在首帧后执行，每处理 64 项让出一次事件循环。继续使用原有串行维护、任务合并、LRU 和在用文件保护；失败通过设置页重试。

## 词库迁移

- 新缓存为应用支持目录中的 `tag-translations.json`，不纳入图片容量清理。
- 优先读取该文件；文件不存在或损坏时尝试旧 SharedPreferences 键 `eh_tag_translations_cache`。JSON 解析和搜索索引构建通过 `compute` 在后台 isolate 完成，主 isolate 只交换完整结果。
- 迁移先验证数据，再写临时文件、核对写入内容并替换正式文件，成功后删除旧键。写入失败保留旧缓存；下载失败或返回无效词库时保留已有有效数据。
- 首次升级仍需读取包含旧词库的偏好文件；迁移后，后续启动不再从偏好设置传输大型词库。

## 阶段记录

启动日志使用 `[startup]` 前缀，包含阶段、进程内累计耗时、阶段耗时和结果：`essential_init`、`first_frame`、`network_ready`、`cache_maintenance`、`translations_ready`、`home_content`。

这些记录只含阶段名与时间，不记录地址、代理凭据、Cookie 或浏览内容。`home_content` 指首页列表请求完成解析和标记，不代表所有封面均已解码。进程内时间不包含 Dart 入口执行前的原生引擎初始化；跨版本首屏比较另用 Android `am start -W` 的 `TotalTime`。

## 2026-10-02 Android 对比

同一华为 VOG-AL10，Flutter 3.13.9，优化前后均为 Profile APK，使用相同签名覆盖安装，保留设置及应用数据，不卸载、不清缓存。基线为 v1.4.1（46）。先独立记录首次升级迁移，再比较五次后续冷启动；只接受 `LaunchState: COLD` 且 Activity 为 OViewer 的样本，系统桌面或更新窗口抢占的记录不计入。

| 样本 | 系统 TotalTime（ms） |
|---|---|
| 基线五次 | 849、840、834、825、824 |
| 优化后首次迁移 | 779 |
| 优化后五次 | 399、395、390、422、390 |

中位数从 834ms 降至 395ms，约减少 53%。优化后五次进程内首帧为 123–138ms；缓存维护和词库就绪记录均位于首帧之后。首次迁移的必要初始化为 323ms，后续为 39–46ms，确认移出偏好设置的大词库不再拖慢每次设置读取。

测试后已恢复原安装包，并确认原版本的词库缓存重新就绪。现场没有 USB iOS 设备，未将 Android 数据外推为 iOS 实测结论。该结果仅代表此设备、构建模式及缓存状态，不承诺所有设备固定启动耗时。
