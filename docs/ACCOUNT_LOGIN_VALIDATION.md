# 账号登录验证记录（Issue #61）

## 实现

- 默认进入“账号登录”，右侧依次为 WebView 登录、手动 Cookie。
- 用户名去除首尾空白，密码保持原样；账号密码不落盘、不进入状态或日志。密码在切换标签、离开页面或登录成功后清空。
- 每次登录使用独立的内存 Cookie 容器，动态读取表单、隐藏字段和会话参数。密码仅向官方论坛 HTTPS 登录操作提交一次；拒绝跨站、降级及重放密码的重定向。
- 请求等待现有代理准备，并使用同一路由；密码请求始终校验 TLS 证书。
- 必须取得完整认证 Cookie，并通过包含对应会员链接及退出登录入口的论坛页面验证后，才提交应用会话。
- 取消、离开页面、退出登录会让旧操作失效；会话写入分阶段检查有效性，并清除取消后产生的部分认证数据。完成通知与最后一次有效性检查之间不再等待异步操作。
- EH 模式不请求 EX；EX 检查失败保留账号登录，不自动切站。设置页面仍沿用现有 Cookie 同步机制。
- 安全验证提示为“因网络原因触发安全验证，前往webview完成验证”，点击才切换，不自动填写网页密码。WebView 首次选中才创建，离开后保留网页但禁止提交后台登录结果。
- Android/iOS 注册入口使用独立的固定地址原生接口，不修改发布页链接接口的允许范围。

## 官方表单核实

2026-10-23 通过官方论坛的 `act=Login&CODE=00` 页面读取 DOM，未提交账号密码：

- 表单方法为 POST，目标为官方论坛 `/index.php`，操作 `act=Login&CODE=01`，携带页面当次返回的 `s`。
- 输入字段为 `UserName`、`PassWord`；隐藏字段为 `referer`、`b`、`bt`。
- `CookieDate=1` 默认选中，`Privacy=1` 默认不选中，提交按钮为 `submit=Log me in`。
- 注册链接为官方论坛 `/index.php?act=Reg&CODE=00`，应用不固化用户提供的会话参数。
- `test/fixtures/account_login_form.html` 保留已核实的字段结构，替换会话与 referer；认证成功、失败等响应为合成测试样本，不冒充真实账号实测。
