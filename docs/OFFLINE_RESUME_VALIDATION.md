# 离线下载暂停恢复验证（Issue #59）

## 场景与实现

针对应用未退出时，暂停下载后点击“继续下载”的等待。基线为 `ede1593` 中的下载协调器；基线和修复版使用相同的下载页面、数据库、图片文件和受控网络。

- 复用当前进程内已准备好的完整目录，恢复时重新读取数据库进度，避免重复下载暂停前刚完成的页面。
- 已验证文件按路径、长度、摘要、修改时间和文件变更时间保存校验记录；未变化时不重新读取内容计算摘要。变化或缺失的文件重新检查并补下载，阅读器仍校验实际内容。
- 已知未完成页先进入下载，已有文件检查同时进行。完成状态必须等待检查结束及损坏页补下载，不能只因为下载队列暂时为空就标记完成。
- 切换来源、切换账号、进程重启、目录不匹配时重新准备；删除清除记录，单页修复使对应记录失效，失败重试允许刷新目录。
- 点击后立即显示恢复状态，禁止重复点击，允许再次暂停或删除。连续状态通知合并为一次列表刷新。
- 主动取消响应流和丢弃错误响应体；旧写入及清理完成后才释放并发名额。数据库和离线文件格式不变。

## 真机方法

Huawei VOG-AL10，Android 10，Flutter 3.16.0 Profile，独立包名 `com.oviewer.oviewer.offline_test`。正式版与日常 Debug 版不参与测试。

入口：`test_driver/offline_resume_benchmark.dart`。使用真实下载协调器、SQLite、文件存储、DownloadBloc 和 DownloadScreen；模拟触摸“继续下载”。网络只提供固定目录和可取消的图片流，目录每页固定延迟 10ms，每页目录包含 40 张图片。

两组各预置 10 / 1000 张有效 PNG，每张 256 KiB，另留一页未完成。每组预热两次且等待文件检查完成，再采集 20 次暂停恢复。P95 采用排序后第 19 个样本。

- 界面反馈：触摸至显示恢复或后续活动状态的首个完成帧。
- 恢复请求：触摸至首次调用剩余图片页请求；不包含服务器响应和图片传输耗时。
- 基线仅替换为历史协调器，保持当前界面和同一夹具，因此不将基线界面耗时当作旧版界面的测量。
- 公网吞吐未测量；这些数据用于验收恢复调度，不代表 EH/EX 服务器或代理的实际下载速度。

## 回归与证据

- 824 项 Flutter 测试通过；52 项版本脚本测试通过；静态分析无新增错误或警告。
- 覆盖目录复用、文件未变化不重复摘要读取、缺失及同长度损坏、修改时间变化、冷启动、会话/来源变化、目录准备中暂停、后台服务失败、重复恢复、删除竞争、并发上限、读取超时、错误响应体停滞、iOS 前后台恢复。
- “先下载、后检查”的测试等待所有新页面写完，确认任务仍未完成，再删除旧文件，确认补下载后才完成。
- 中英文页面测试覆盖等待状态、禁用重复点击、暂停、删除和失败后再次操作。
- 本地完整记录：`build/issue59-fixed-final-captured.log`、`build/issue59-baseline-final-captured.log`、`build/issue59-final-full-tests.log`、`build/issue59-final-analysis.log`、`build/issue59-version-tests.log`。

## 复测与交付

仅在独立测试包运行该入口，入口本身会校验包名。Profile 构建使用本地 Gradle 初始化脚本将 `profile.applicationIdSuffix` 设置为 `.offline_test`，显示名称设为 `OViewer Offline Test`，然后通过 `-Ptarget=<入口绝对路径>` 构建。不得使用正式版包名。

历史基线从上述提交读取协调器源码，仅补充当前界面所需的 `resumingIds` 空集合接口，并通过 `runResumeBenchmark` 的工厂参数注入。运行时逐行刷新日志，必须取得两个完整分组及 `COMPLETE` 标记；不能用被截断的 Android 单条日志统计。

代码推送至 `dev`，不修改构建产物、签名或版本号，不监听 Actions，不自动正式发布。独立测试应用已卸载；正式版与 Debug 版的版本号、首次安装时间、最近更新时间核对一致，未被覆盖。
